# CORVAX v1.0 RC2 — تقرير المراجعة الحازمة

## الرأي التنفيذي

النظام أصبح **مرشحًا قويًا للتجربة المؤسسية**، لكنه لا يستحق وصف Production Final حتى تُغلق الملاحظات الحرجة والعالية أدناه. هذا التقرير لا يجامل: وجود شاشة أو API لا يعني اكتمال الضبط أو الامتثال أو قابلية الاعتماد.

## الملاحظات الحرجة

### CR-01 — التكاملات الرسمية غير مكتملة

**الحالة:** مفتوحة — مانعة للإنتاج الرسمي.

- ZATCA Phase 2 غير متصلة بـ CSID وSandbox/Production.
- البنوك ومدد وقوى ومقيم والتأمينات تحتاج بيانات اعتماد رسمية.

**الإجراء المطلوب:** تنفيذ التكامل على بيئة الاختبار الرسمية، توثيق الردود والأخطاء وإعادة الإرسال، ثم قبول المستخدمين والجهة المختصة.

### CR-02 — لا يوجد اختبار اختراق مستقل

**الحالة:** مفتوحة — مانعة لتخزين بيانات حساسة على الإنترنت.

**الإجراء المطلوب:** فحص SAST/DAST، اختبار فصل الشركات، المصادقة والصلاحيات، إدارة الجلسات، المرفقات، وواجهات API بواسطة جهة مستقلة.

### CR-03 — لم يتم Parallel Run أو ترحيل بيانات فعلية

**الحالة:** مفتوحة — مانعة لاستبدال النظام الحالي.

**الإجراء المطلوب:** ترحيل أرصدة افتتاحية، تشغيل شهر كامل بالتوازي، مطابقة الرواتب والمخزون والبنوك والقوائم، واعتماد رسمي من الإدارات.

## الملاحظات العالية

### HI-01 — وجود endpoints تجريبية بأرقام مالية ثابتة

**الدليل:** `backend/app/api/modules.py` يتضمن بيانات عرض وقوائم مالية ثابتة ضمن endpoints قديمة.

**الخطر:** إمكانية أن يعتمد مستخدم أو تكامل على أرقام ليست ناتجة من دفتر الأستاذ.

**الإجراء:** تعطيل endpoints التجريبية في Staging/Production أو نقلها إلى namespace تجريبي واضح، ومنع عرضها عند `SEED_DEMO_DATA=false`.

### HI-02 — إنشاء الجداول عند بدء التطبيق إلى جانب Alembic

**الدليل:** `Base.metadata.create_all(bind=engine)` داخل lifespan في `backend/app/main.py`.

**الخطر:** اختلاف مخطط الإنتاج عن سجل migrations أو إنشاء جدول قبل تطبيق migration المعتمد.

**الإجراء:** السماح بـ create_all في بيئة development فقط، وإلزام Staging/Production بـ `alembic upgrade head` قبل تشغيل التطبيق.

### HI-03 — سجل المراجعة ليس WORM أو Hash-Chained

**الخطر:** مسؤول قاعدة بيانات قد يعدل سجل التدقيق مباشرة.

**الإجراء:** إضافة سلسلة Hash، تصدير دوري إلى مخزن غير قابل للتعديل، ومراقبة أي انقطاع في التسلسل.

### HI-04 — الحقول الحساسة غير مشفرة على مستوى التطبيق

**النطاق:** بيانات الهوية والرواتب والبنوك والضرائب والمفاتيح الخارجية.

**الإجراء:** تصنيف البيانات، تشفير حقول محددة، تدوير المفاتيح، واستخدام Secret Manager.

### HI-05 — لم يتم اختبار الأداء على حجم مؤسسي

**الإجراء:** اختبار مستخدمين متزامنين، ملايين القيود، تقارير التوحيد، POS متعدد الفروع، الرواتب والتصنيع، مع أهداف زمن استجابة واضحة.

### HI-06 — الاستعادة اختُبرت محليًا وليست Disaster Recovery كاملة

**الإجراء:** نسخة مشفرة خارج الخادم، Point-in-Time Recovery، Restore Drill على خادم منفصل، واعتماد RPO/RTO.

### HI-07 — بعض المعايير ما تزال بنطاق مبسط

- IFRS 9: النموذج المبسط، لا يشمل نموذج المراحل الكامل وPD/LGD/EAD.
- IFRS 16: التعديلات وإعادة القياس والحالات المعقدة غير مكتملة.
- IFRS 18: الإفصاحات والتجميع ومقاييس الإدارة ليست نهائية.
- التوحيد: الشهرة وNCI والاستحواذ والأرباح غير المحققة والضريبة المؤجلة غير مكتملة.

**الإجراء:** لا تفعيل الحالات المعقدة للعملاء قبل استكمال المحرك واعتماد السياسة من مختص.

## الملاحظات المتوسطة

### MD-01 — الواجهة الحالية وظيفية وليست التصميم النهائي

**الإجراء:** تنفيذ Design System عالمي مستقل بعد تثبيت الوظائف، مع اختبارات Accessibility، RTL/LTR، كثافة الجداول والجوال والطباعة.

### MD-02 — ملف Dashboard كبير وأحادي

**الخطر:** صعوبة الصيانة والاختبار وتضارب التعديلات.

**الإجراء:** تقسيم الصفحات إلى مكونات وموديولات مستقلة مع Route-level code splitting واختبارات مكونات.

### MD-03 — إدارة المرفقات والأدلة تحتاج تقوية

**الإجراء:** Object Storage، صلاحيات تنزيل، تشفير، فحص Malware، Versioning، Retention وLegal Hold.

### MD-04 — اعتماد السياسات لم يتم على بيانات الشركة

**الإجراء:** اعتماد دليل الحسابات، الإهلاك، المصروفات المقدمة، الإيراد، الإيجار، ECL، المخزون، الرواتب والإقفال بواسطة أصحاب الصلاحية.

## نقاط قوة مثبتة

- فصل شركات وصلاحيات وMaker-Checker.
- دفتر أستاذ وقوائم وإقفالات مترابطة.
- محركات المصروفات المقدمة والاستحقاقات والأصول والعملات والتوحيد.
- المخزون والتصنيع والتكاليف والصيانة والجودة.
- الموارد البشرية والرواتب والحضور والإجازات ونهاية الخدمة.
- الحوكمة والمراجعة وITSM وCRM.
- بوابة تأكيد مالي تمنع الاعتماد مع الموانع الجوهرية.
- 115 جدولًا وترحيلات حتى `e11000000001`.
- نجاح الاختبارات التراكمية حتى RC2.
